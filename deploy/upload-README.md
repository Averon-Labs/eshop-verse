# Upload packages — EShop Verse demo

Generated by `deploy/build-release.sh` (bash) or `deploy/build-release.ps1` (Windows); do not edit by
hand (the source of truth is the repository).

| Package | Goes to | Extracts as |
|---------|---------|-------------|
| `eshopverse-full-deploy.zip` | `htdocs/` | **everything in one step:** `index.php`, `.htaccess`, `index.html`, `assets/`, `fonts/`, `eshopverse_app/` (including `eshopverse_app/.env`) |
| `eshopverse_app.zip` | `htdocs/` | folder `eshopverse_app/` beside `index.php` |
| `eshopverse-admin.zip` | `htdocs/` | `index.html`, `assets/`, `fonts/` at the root (overwrite) |
| `htdocs/index.php`, `htdocs/.htaccess` | `htdocs/` | loose files — enable "Show hidden files" for `.htaccess` |

`output/htdocs/` is the complete host root, so uploading that one folder is equivalent to
uploading both archives plus the front controller.

## Full deployment (one archive)

Use `eshopverse-full-deploy.zip` when the whole server has to be replaced instead of single files.

1. **Back up the host first:** `htdocs/eshopverse_app/.env`, `htdocs/eshopverse_app/storage/`, and
   `htdocs/eshopverse_app/storage/app/product-images/`.
2. **Fill `eshopverse_app/.env` inside the archive before uploading.** Its `DB_HOST`, `DB_DATABASE`,
   `DB_USERNAME`, and `DB_PASSWORD` are `CHANGE_ME_*` placeholders, and `APP_KEY` must be the key the
   host already uses. The site cannot connect to MySQL until they are set. Open the archive, edit the
   file, and save it back into the archive.
3. Extract the archive into `htdocs/`, replacing `index.php`, `.htaccess`, `index.html`, `assets/`,
   `fonts/`, and `eshopverse_app/`. Enable "Show hidden files" so `.htaccess` and `.env` are written.
4. Restore any `storage/app/product-images/` files from the backup, and keep `storage/` and
   `bootstrap/cache/` writable.
5. If the host caches configuration, run `php artisan config:clear` and restart the app.
6. Open the site and hard-refresh.

The archive is secret-free when produced: it only contains `.env` when
`output/eshopverse-backend.env` exists locally, and that file holds placeholders instead of real
database credentials.

## Partial upload

1. Back up the host's `htdocs/index.html`, `assets/`, `fonts/`, and `htdocs/eshopverse_app/.env`.
2. Extract `eshopverse_app.zip` into `htdocs/`. It does **not** contain `.env`, logs, `bootstrap/cache`
   contents, the test suite, or Laravel's welcome view; `vendor/` is included because the host has no
   Composer.
3. Extract `eshopverse-admin.zip` into `htdocs/`, then delete old hashed files in `assets/`.
4. Upload `index.php` and `.htaccess` into `htdocs/` (hidden files must be visible).
5. Keep `eshopverse_app/storage/` and `eshopverse_app/bootstrap/cache/` writable, and keep the host's
   `storage/app/product-images/` contents.
6. Open the site and hard-refresh.

## Checks after upload

| Request | Expected |
|---------|----------|
| `GET /` | admin sign-in SPA — never a Laravel page |
| `GET /login` | SPA sign-in route (needs the root `.htaccess`) |
| `GET /privacy`, `GET /terms` | public legal pages (no sign-in) |
| `GET /up` with `Accept: application/json` | `{"status":"up"}` |
| `GET /api/v1/products` | JSON product list |

`output/` is git-ignored; never commit the archives or the staged application.
